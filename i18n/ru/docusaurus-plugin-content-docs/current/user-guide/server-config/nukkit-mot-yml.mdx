# nukkit-mot.yml

Расширенная конфигурация сервера Nukkit-MOT. Настройки сгруппированы и отсортированы по категориям.

Стандартные настройки сервера Minecraft описаны в [server.properties](server-properties.mdx).

## network-settings (Настройки сети) {#network-settings}

### `nethernet` {#network-settings-nethernet}

Настройки транспорта NetherNet (WebRTC), работает параллельно с RakNet

NetherNet — основанный на WebRTC транспорт, которым Bedrock Edition приходит на смену RakNet: клиенты версий 1.21.90+ могут подключаться через него (сначала — из сетей с ограничениями, где заблокирован чистый UDP), а с Bedrock 1.26.50 это транспорт клиента по умолчанию. Nukkit-MOT прослушивает оба транспорта одновременно — старые клиенты остаются на RakNet, клиенты NetherNet заходят через HTTP-сигналинг + WebRTC

Транспорты используют сеть так:

- Сигналинг по **TCP на порту `server-port`** (UDP-сторона остаётся за RakNet) — откройте `server-port` для TCP в файрволе, иначе игроки NetherNet вовсе не смогут подключиться
- Медиатрафик (игровые данные) по **UDP** — по умолчанию закреплён за портом `19134` (ICE mux, один порт обслуживает всех участников); меняется через [`server-udp-ports`](server-properties.mdx#server-udp-ports) (`0` — снова системное назначение), там же описано, что делать, если UDP медиатрафика недоступен

Мониторинг: `/status` выводит блок NetherNet за последние 10 минут (принятые входы, ICE-подключения, завершённые рукопожатия); `/status full` добавляет трафик и счётчики отключений. Пока NetherNet отключён, блок скрыт.

```yaml
network-settings:
  nethernet:
    enabled: true
    ice-servers: []
    identity-file: keys/nethernet-identity.pem
    identity-domain: ''
```

#### `enabled`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| Boolean   | on            |

Включён по умолчанию параллельно с RakNet

Пока включён, сигналинг использует `server-port` по TCP, а медиатрафик закреплён за UDP `19134` (один ICE mux порт обслуживает всех участников — см. [`server-udp-ports`](server-properties.mdx#server-udp-ports); `0` возвращает системное назначение портов)

Установите `false`, чтобы работать только с RakNet — TCP-эндпоинт сигналинга и порт медиатрафика исчезнут, больше ничего не изменится

#### `ice-servers`
| Тип данных    | Значение по умолчанию |
|--------------|---------------|
| `List<String>` | []          |

Дополнительные ICE STUN/TURN-серверы, например `stun:stun.l.google.com:19302`

Учётные данные TURN указываются прямо в URL: `turn:user:pass@host:port?transport=udp`

Добавьте TURN-релей, когда игроки за симметричным NAT не могут установить прямой путь для медиатрафика — полный чек-лист при недоступном медиатрафике см. в [`server-udp-ports`](server-properties.mdx#server-udp-ports)

#### `identity-file`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| String    | keys/nethernet-identity.pem |

PEM-файл идентичности оператора, создаётся при первом запуске — сохраните его

Его замена заставит всех возвращающихся игроков заново подтверждать запрос доверия

Запускаете несколько серверов? Расшарьте один файл идентичности между ними, чтобы выглядеть единым оператором

#### `identity-domain`

Имя оператора в запросе доверия на клиенте; если пусто, используется MOTD

Только отображаемый текст — его можно менять в любой момент, не меняя ключ идентичности

### `rak-cookie-mode`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| String    | active        |

Режим cookie RakNet для защиты соединений. Доступные значения:

| Значение | Описание |
|-------|-------------|
| `active` | Ключ генерируется и управляется сервером. Обрабатывает `ID_OPEN_CONNECTION_REQUEST_1` и отвечает на него с помощью cookie без сохранения состояния (по умолчанию) |
| `offloaded` | Ключ неизвестен. Игнорирует `ID_OPEN_CONNECTION_REQUEST_1`. При `ID_OPEN_CONNECTION_REQUEST_2` проверяет, что метка времени актуальна. Подпись игнорируется |
| `offloaded_psk` | Ключ известен. Игнорирует `ID_OPEN_CONNECTION_REQUEST_1`. При `ID_OPEN_CONNECTION_REQUEST_2` проверяет, что метка времени актуальна, и проверяет подпись cookie |
| `off` | Принимает любой cookie при `ID_OPEN_CONNECTION_REQUEST_2` |
| `none` | Cookie не отправляется и не ожидается. В этом режиме версию протокола RakNet определить невозможно |
| `stateless` | Выполняет полное рукопожатие cookie и восстанавливает версию протокола RakNet из cookie, но не проверяет подпись |

:::note
Если вы не можете зайти на сервер (особенно при использовании прокси), попробуйте установить значение `offloaded`.

Для обратной совместимости значение `true` трактуется как `active`, а `false` — как `off`.
:::

### `timeout-milliseconds`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| Integer   | 25000         |

сколько времени сервер должен ждать до отключения игрока, если от клиента нет ответа

:::

### `enable-proxy-protocol`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| Boolean   | off           |

Включает разбор HAProxy Proxy Protocol v2 для UDP-прокси, таких как FRP.

Когда доверенный прокси отправляет корректный заголовок PPv2, Nukkit-MOT заменяет исходный адрес прокси на реальный адрес клиента.
Это позволяет журналам, банам и плагинам, работающим с IP, видеть реальный IP игрока вместо IP прокси.

:::warning
Включайте это только если ваш сервер находится за совместимым UDP-прокси.
Источники прокси из белого списка должны отправлять корректный заголовок PPv2.
:::

### `proxy-protocol-whitelist`
| Тип данных    | Значение по умолчанию      |
|--------------|--------------------|
| `List<String>` | ["127.0.0.1/32", "::1/128"] |

Список доверенных IP-адресов или CIDR-диапазонов источников прокси, которым разрешено отправлять заголовки Proxy Protocol.

Здесь указываются адреса прокси, а не адреса игроков.
Примеры: `127.0.0.1/32`, `10.0.0.0/8`, `203.0.113.5/32`, `::1/128`

:::note
Поддерживаются записи как IPv4/CIDR, так и IPv6/CIDR.

Локальные IPv6-адреса считаются доверенными по умолчанию.

Если список пуст, для Proxy Protocol доверенными считаются все исходные IP, что менее безопасно.

Пакеты без заголовка или с некорректным заголовком, приходящие из доверенного источника, будут отброшены.
:::

### `worlds`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| Map       |               |

Пример:
```yaml
worlds:
  my_world:
    generator: normal
    seed: 12345
    generator-settings: ""
  my_flat_world:
    generator: flat
    seed: 0
    generator-settings: ""
```

Каждая запись мира поддерживает:
- `generator` - Тип генератора мира (по умолчанию: `normal`)
- `seed` - Сид мира (по умолчанию: `0`)
- `generator-settings` - Специфичные для генератора настройки (по умолчанию: пусто)

### `vanilla-armor-reduction`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| Boolean   | on            |

Использовать ванильную формулу снижения урона бронёй.

При включении снижение урона следует ванильной формуле Bedrock: нелинейная кривая брони/прочности, учитывающая зачарование `Breach`, и детерминированный фактор защиты зачарований (EPF), ограниченный значением 20 (без случайного множителя). Модификаторы урона применяются в ванильном порядке: `ARMOR → ARMOR_ENCHANTMENTS → RESISTANCE → ABSORPTION`.

При отключении вместо неё используется прежняя линейная формула: броня снижает урон на `damage × armorPoints × 4%`, EPF масштабируется случайным множителем `50%–100%`, а `toughness`/`breach` игнорируются.

:::note
Держите эту опцию включённой, если только вам не нужно сохранить боевое поведение до версии 1.21 для обратной совместимости.
:::

### `vanilla-knockback-resistance`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| Boolean   | on            |

Использовать ванильную формулу сопротивления отбрасыванию брони.

При включении каждая надетая часть незеритовой брони блокирует 10% входящего отбрасывания (полный комплект — 40%), что соответствует ванильному поведению Bedrock. Общее сопротивление также синхронизируется с клиентом как атрибут, поэтому предсказание на стороне клиента совпадает с сервером.

При отключении броня больше не даёт сопротивления отбрасыванию, и игроки получают отбрасывание в полную силу (прежнее поведение). Сопротивление отбрасыванию из других источников, например атрибутов сущностей, заданных плагинами, не затрагивается.

## custom-block-settings (Настройки кастомных блоков) {#custom-block-settings}

### `auto-download-vanilla-palette`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| Boolean   | on            |

Автоматически загружать ванильные палитры блоков (`vanilla_palette_*.nbt`) с официального зеркала при их отсутствии.

Это необходимо для поддержки кастомных блоков на нескольких версиях протокола клиента. Файлы кэшируются в папке `bin/` и проверяются с помощью SHA256.

Если отключено, вам потребуется самостоятельно подготовить файлы палитр в папке `bin/`.

### `use-hashed-block-network-ids`
| Тип данных | Значение по умолчанию |
|-----------|---------------|
| Boolean   | on            |

Отправлять хэшированные сетевые ID блоков (`blockNetworkIdsHashed`) клиентам 1.19.80+, включая клиентов NetEase, вместо устаревших runtime ID.

Включено по умолчанию даже без кастомных блоков; хэшированные ID неизменны между версиями.

:::note
Не влияет на версии протокола ниже 1.19.80.

Всегда принудительно включено, когда зарегистрированы кастомные блоки.
:::

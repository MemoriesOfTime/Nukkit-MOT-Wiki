# server.properties

Измените рабочую конфигурацию сервера, чтобы настроить некоторые базовые функции.

Это стандартные настройки сервера Minecraft, определяемые в файле `server.properties`. Расширенные настройки Nukkit-MOT описаны в [nukkit-mot.yml](nukkit-mot-yml.mdx).

:::note

## `server-port`
| Тип данных | Значение по умолчанию |
|------------|-----------------------|
| Integer    | 19132                 |

порт сервера

:::note

:::

## `server-udp-ports`
| Тип данных | Значение по умолчанию |
|------------|-----------------------|
| Integer / String | 19134           |

UDP-порт/диапазон для медиатрафика NetherNet (WebRTC), синтаксис как у Bedrock Dedicated Server:

| Значение | Описание |
|----------|----------|
| `19134` | Один ICE mux порт обслуживает все медиасоединения (по умолчанию) |
| `0` | Порты медиатрафика назначаются системой на каждое соединение |
| `N` | Закрепляет один порт медиатрафика |
| `A-B` | Закрепляет диапазон портов медиатрафика |
| `[ip:]external[-external]:internal[-internal]` | Дополнительно публикует внешнее отображение портов, например за NAT. Диапазоны по обе стороны от двоеточия должны быть одинаковой длины |

Записи могут содержать IP-префикс (для IPv6 — в квадратных скобках, например `[2001:db8::1]:...`); несколько записей через запятую накапливают объявленные IP, но диапазон портов и смещение должны совпадать

:::warning
Настроенные порты не должны перекрывать `server-port` (его UDP-сторона принадлежит RakNet) и порт IPv6-прослушивания; некорректные значения прерывают запуск вместо отката к автоматическим портам.
:::

### Недоступен UDP медиатрафика — игроки застревают на подключении {#nethernet-media-unreachable}

Когда игроки NetherNet застревают на «Подключении» или отключаются сразу после входа, путь UDP для медиатрафика обычно заблокирован. Сервер сообщает об этом сам — в логе появляется предупреждение:

```
NetherNet media may be unreachable: 6 ICE attempts, 0 connected in the last 5 minutes.
Check the firewall/port forwarding for the media UDP window udp/... (server-udp-ports)
```

а `/status` показывает рост принятых входов при ICE-подключениях, равных 0.

Исправляется так:

1. Разрешите входящий UDP для порта медиатрафика — в файрволе хоста, группах безопасности облака и пробросе на роутере. По умолчанию закреплён единственный порт `19134` — достаточно открыть/пробросить UDP `19134`; непредсказуемые системные порты бывают только при `server-udp-ports=0` — сначала закрепите диапазон (например, `server-udp-ports=50000-50010`) и пробросьте его
2. Публичные порты отличаются от внутренних (NAT-отображение)? Опубликуйте внешнюю сторону: `server-udp-ports=60000-60010:50000-50010`
3. Всё ещё не работает для игроков за симметричным NAT? Через TURN-релей в [`network-settings.nethernet.ice-servers`](nukkit-mot-yml.mdx#network-settings-nethernet) можно передавать медиатрафик дальше:

```yaml
network-settings:
  nethernet:
    ice-servers:
      - stun:stun.l.google.com:19302
      - 'turn:user:pass@turn.example.com:3478?transport=udp'
```

:::tip Диагностика по цифрам /status
- **Принятые входы** растут, а **ICE-подключений всё ещё 0** — UDP для медиатрафика заблокирован; примените шаги выше
- **ICE-подключения** растут, но **завершённых рукопожатий** мало — не проходит рукопожатие DTLS, обычно это intermediary-устройства, вмешивающиеся в UDP
- Много **отключений после подключения** — тайм-ауты NAT или джиттер соединения
:::

## `server-ipv6-port`
| Тип данных | Значение по умолчанию |
|------------|-----------------------|
| Integer    | -1                    |

порт для опционального IPv6-прослушивания

:::note

IPv6-прослушивание отключено, если значение — `0` или меньше (по умолчанию `-1`)

чтобы включить его, укажите корректный порт, отличный от `server-port`

:::

## `server-ipv6`
| Тип данных | Значение по умолчанию |
|------------|-----------------------|
| String     | ::                    |

IPv6-адрес, к которому привязывается опциональное IPv6-прослушивание

должен быть корректным IPv6-адресом; оставьте поле пустым, чтобы отключить IPv6-прослушивание

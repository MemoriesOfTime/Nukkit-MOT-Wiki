# server.properties

修改服务器的运行配置，以此来定制一些基本功能。

这些是定义在 `server.properties` 中的标准 Minecraft 服务器设置。如需 Nukkit-MOT 高级设置，请参阅 [nukkit-mot.yml](nukkit-mot-yml.mdx)。

## `motd`
| 数据类型   | 默认值              |
|--------|------------------|
| String | Minecraft Server |

服务器名称/显示在服务器列表上的文本

:::note

不能为空

:::

## `sub-motd`
| 数据类型   | 默认值                   |
|--------|-----------------------|
| String | Powered by Nukkit-MOT |

motd 的第二行

:::note

只有当在游戏中的好友列表中查看服务器时，才会显示给本地网络中的玩家

自 1.16.210 以来不能为空

:::

## `server-port`
| 数据类型    | 默认值   |
|---------|-------|
| Integer | 19132 |

服务器的端口

:::note

同一端口不能运行多个服务器

如果不能访问请检查防火墙

基岩版使用 UDP 协议

启用 NetherNet 时，同一端口还会通过 TCP 提供 WebRTC 信令，因此也需要放行该端口的 TCP

:::

## `server-ip`
| 数据类型   | 默认值     |
|--------|---------|
| String | 0.0.0.0 |

服务器的 IP 地址

:::note

同一端口不能运行多个服务器

如果不能访问请检查防火墙

基岩版使用 UDP 协议

该地址同时绑定 RakNet UDP 监听器和 NetherNet TCP 信令

:::

## `server-udp-ports`
| 数据类型    | 默认值 |
|---------|-----|
| Integer / String | 19134 |

NetherNet（WebRTC）媒体使用的 UDP 端口/窗口，语法与 Bedrock 官方服务端一致：

| 取值 | 说明 |
|-----|-----|
| `19134` | 单个 ICE 复用端口服务所有媒体连接（默认） |
| `0` | 每个连接的媒体端口由系统自动分配 |
| `N` | 钉住单个媒体端口 |
| `A-B` | 钉住一段媒体端口窗口 |
| `[ip:]external[-external]:internal[-internal]` | 同时发布外部端口映射（例如在 NAT 后）。冒号两侧的范围长度必须一致 |

条目可带 IP 前缀（IPv6 需加方括号，如 `[2001:db8::1]:...`），多个逗号分隔的条目会累积发布的 IP，但端口窗口与偏移必须一致

:::warning
配置的端口不得覆盖 `server-port`（其 UDP 侧属于 RakNet）或 IPv6 监听器端口；非法取值会中止启动，而不是回退到自动分配端口。
:::

### 媒体 UDP 不通——玩家卡在连接 {#nethernet-media-unreachable}

当 NetherNet 玩家卡在"连接中"或加入后立刻掉线时，通常是媒体 UDP 路径被阻断。服务器会自行报告——日志中出现告警：

```
NetherNet media may be unreachable: 6 ICE attempts, 0 connected in the last 5 minutes.
Check the firewall/port forwarding for the media UDP window udp/... (server-udp-ports)
```

同时 `/status` 里"接受的加入"在增长而 ICE 连通数恒为 0。

按以下方法解决：

1. 放行媒体 UDP 端口的入站——主机防火墙、云安全组、路由器端口转发都要放行。默认只钉一个端口 `19134`，直接放行/转发 UDP `19134` 即可；只有设为 `0` 时端口才由系统分配、不可预知——先钉住窗口（如 `server-udp-ports=50000-50010`）再转发
2. 公网端口与内部端口不一致（NAT 映射）？改为发布外部一侧：`server-udp-ports=60000-60010:50000-50010`
3. 对称 NAT 后的玩家仍然连不上？在 [`network-settings.nethernet.ice-servers`](nukkit-mot-yml.mdx#network-settings-nethernet) 中配置 TURN 中继转发媒体：

```yaml
network-settings:
  nethernet:
    ice-servers:
      - stun:stun.l.google.com:19302
      - 'turn:user:pass@turn.example.com:3478?transport=udp'
```

:::tip 按 /status 的数字排查
- **接受的加入**在增长而 **ICE 连通数恒为 0** —— 媒体 UDP 被阻断；按上面的步骤处理
- **ICE 连通数**在增长但**完成的握手**很少 —— DTLS 握手失败，通常是中间设备干扰 UDP
- **连接后掉线**很多 —— NAT 超时或链路抖动
:::

## `server-ipv6-port`
| 数据类型    | 默认值  |
|---------|------|
| Integer | -1   |

可选 IPv6 监听器的端口

:::note

当此值为 `0` 或更低时（默认 `-1`），IPv6 监听器处于禁用状态

要启用它，请设置一个与 `server-port` 不同的有效端口

:::

## `server-ipv6`
| 数据类型   | 默认值  |
|--------|------|
| String | ::   |

可选 IPv6 监听器绑定的 IPv6 地址

必须是有效的 IPv6 地址；留空则禁用 IPv6 监听器

## `view-distance`
| 数据类型    | 默认值 |
|---------|-----|
| Integer | 8   |

最大视距（以区块为单位）

更大的值 = 加载更多区块 = 更多的内存和 CPU 使用

## `max-players`
| 数据类型    | 默认值 |
|---------|-----|
| Integer | 50  |

服务器允许的最大玩家人数

## `language`
| 数据类型   | 默认值 |
|--------|-----|
| String | eng |

Nukkit 使用的默认语言

## `force-language`
| 数据类型    | 默认值 |
|---------|-----|
| Boolean | off |

强制使用服务器端翻译

只有在您有插件来实现这些翻译时才启用

## `shutdown-message`
| 数据类型   | 默认值           |
|--------|---------------|
| String | §cServer closed |

当您停止服务器时向玩家显示的消息

可以使用颜色符号`§`，换行请使用 `§n`。

## `gamemode`
| 数据类型    | 默认值 |
|---------|-----|

0 = 生存, 1 = 创造, 2 = 冒险, 3 = 旁观

每次加入时将玩家游戏模式设置为默认游戏模式

|---------|-----|

服务器的默认难度（0-3）

## `hardcore`
| 数据类型    | 默认值 |
|---------|-----|
| Boolean | off |

玩家死亡后将其封禁

## `pvp`
| 数据类型    | 默认值 |
|---------|-----|
| Boolean | on  |

是否启用玩家对战

## `level-name`
| 数据类型   | 默认值   |
|--------|-------|

默认世界的名称

## `level-seed`
| 数据类型   | 默认值 |

| String |     |

默认世界的种子

| 数据类型   | 默认值     |
|--------|---------|

| 数据类型   | 默认值 |

| 数据类型    | 默认值 |
|---------|-----|
| Integer | 10  |

非管理员(OP)玩家无法在区块内建造或破坏方块的生成保护区域大小（以方块为单位）

## `white-list`

| Boolean | off |

仅允许白名单中的玩家加入服务器

| 数据类型    | 默认值 |
|---------|-----|
| Boolean | off |

## `auto-save`
| 数据类型    | 默认值 |
|---------|-----|
| Boolean | on  |

自动保存世界、玩家数据

:::note

如果禁用，则对世界的更改不会自动保存，即使在卸载时也是如此，如果需要可以使用插件手动保存

:::

## `enable-rcon`
| 数据类型    | 默认值 |
|---------|-----|
| Boolean | off |

启用远程控制台访问

:::note

RCON 不是一个非常安全的远程控制服务器的方式

RCON 可以使用与服务器相同的端口（TCP 协议）

:::

详见：https://developer.valvesoftware.com/wiki/Source_RCON_Protocol

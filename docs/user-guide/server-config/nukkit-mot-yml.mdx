## network-settings (Network Settings) {#network-settings}

### `nethernet` {#network-settings-nethernet}

NetherNet (WebRTC) transport settings, runs alongside RakNet

NetherNet is the WebRTC-based transport Bedrock Edition uses to succeed RakNet: clients 1.21.90+ can join over it (starting with restricted networks where plain UDP is blocked), and since Bedrock 1.26.50 it is the client's default transport. Nukkit-MOT listens on both transports at once — legacy clients keep RakNet, NetherNet clients join over HTTP signaling + WebRTC

The two transports use the network like this:

- Signaling over **TCP on `server-port`** (RakNet keeps the UDP side) — open `server-port` for TCP in the firewall, otherwise NetherNet players cannot connect at all
- Media (game traffic) over **UDP** — pinned to `19134` by default, a single ICE mux port that serves all peers; change it (or set `0` for system-assigned ports) via [`server-udp-ports`](server-properties.mdx#server-udp-ports), which also explains what to do when media UDP is unreachable

<DefaultPortsGrid />

Monitoring: `/status` prints a NetherNet block covering the last 10 minutes (joins accepted, ICE connections, completed handshakes); `/status full` adds media traffic and drop counters. The block is hidden while NetherNet is disabled.

```yaml
network-settings:
  nethernet:
    enabled: true
    ice-servers: []
    identity-file: keys/nethernet-identity.pem
    identity-domain: ''
```

#### `enabled`
| Data Type | Default Value |
|-----------|---------------|
| Boolean   | on            |

Enabled by default alongside RakNet

While enabled, signaling shares `server-port` over TCP and media pins UDP `19134` (one ICE mux port serves all peers — see [`server-udp-ports`](server-properties.mdx#server-udp-ports); `0` reverts media to system-assigned ports)

Set to `false` to run RakNet only — the TCP signaling endpoint and the media port disappear, nothing else changes

#### `ice-servers`
| Data Type    | Default Value |
|--------------|---------------|
| `List<String>` | []          |

Extra ICE STUN/TURN servers, e.g. `stun:stun.l.google.com:19302`

TURN credentials go in the URL: `turn:user:pass@host:port?transport=udp`

Add a TURN relay when players behind symmetric NAT cannot establish a direct media path — see [`server-udp-ports`](server-properties.mdx#server-udp-ports) for the full media-unreachable checklist

#### `identity-file`
| Data Type | Default Value |
|-----------|---------------|
| String    | keys/nethernet-identity.pem |

Operator identity PEM file, generated on first start, keep it

Changing it makes all returning players re-confirm the trust prompt

Running several servers? Share one identity file across them to present as the same operator

#### `identity-domain`

|-----------|---------------|

### `rak-cookie-mode`
| Data Type | Default Value |
|-----------|---------------|
| String    | active        |

RakNet cookie mode for connection security. Available values:

| Value | Description |
|-------|-------------|
| `active` | Key is generated and managed by the server. Handles and responds to `ID_OPEN_CONNECTION_REQUEST_1` with a stateless cookie (default) |
| `offloaded` | Key is unknown. Ignores `ID_OPEN_CONNECTION_REQUEST_1`. On `ID_OPEN_CONNECTION_REQUEST_2`, verifies timestamp is recent. Signature is ignored |
| `offloaded_psk` | Key is known. Ignores `ID_OPEN_CONNECTION_REQUEST_1`. On `ID_OPEN_CONNECTION_REQUEST_2`, verifies timestamp is recent and checks cookie signature |
| `off` | Accepts any cookie at `ID_OPEN_CONNECTION_REQUEST_2` |
| `none` | No cookie is sent or expected. The RakNet protocol version cannot be recovered in this mode |
| `stateless` | Handles the full cookie handshake and recovers the RakNet protocol version from the cookie, but does not validate the signature |

:::note
If you cannot join the server (especially when using a proxy), try setting this to `offloaded`.

For backward compatibility, `true` is treated as `active` and `false` is treated as `off`.
:::

### `enable-proxy-protocol`
| Data Type | Default Value |
|-----------|---------------|
| Boolean   | off           |

Enables HAProxy Proxy Protocol v2 parsing for UDP proxies such as FRP.

When a trusted proxy sends a valid PPv2 header, Nukkit-MOT replaces the proxy source address with the real client address.
This allows IP-based logs, bans, and plugins to see the player's real IP instead of the proxy IP.

:::warning
Enable this only when your server is behind a compatible UDP proxy.
Whitelisted proxy sources must send a valid PPv2 header.
:::

### `proxy-protocol-whitelist`
| Data Type    | Default Value      |
|--------------|--------------------|
| `List<String>` | ["127.0.0.1/32", "::1/128"] |

List of trusted proxy source IPs or CIDR ranges allowed to send Proxy Protocol headers.

Use proxy addresses here, not player addresses.
Examples: `127.0.0.1/32`, `10.0.0.0/8`, `203.0.113.5/32`, `::1/128`

:::note
Both IPv4/CIDR and IPv6/CIDR entries are supported.

IPv6 local addresses are trusted by default.

If the list is empty, all source IPs are trusted for Proxy Protocol, which is less secure.

Headerless or invalid packets coming from a whitelisted source will be dropped.
:::

### `vanilla-armor-reduction`
| Data Type | Default Value |
|-----------|---------------|
| Boolean   | on            |

Use the vanilla armor damage reduction formula.

When enabled, damage reduction follows the vanilla Bedrock formula: a non-linear armor/toughness curve that accounts for the `Breach` enchantment, and a deterministic Enchantment Protection Factor (EPF) capped at 20 (no random multiplier). Damage modifiers are applied in the vanilla order: `ARMOR → ARMOR_ENCHANTMENTS → RESISTANCE → ABSORPTION`.

When disabled, the legacy linear formula is used instead: armor reduces `damage × armorPoints × 4%`, EPF is scaled by a random `50%–100%` multiplier, and `toughness`/`breach` are ignored.

:::note
Keep this enabled unless you need to preserve pre-1.21 combat behavior for backwards compatibility.
:::

### `vanilla-knockback-resistance`
| Data Type | Default Value |
|-----------|---------------|
| Boolean   | on            |

Use the vanilla armor knockback resistance formula.

When enabled, each worn netherite armor piece resists 10% of incoming knockback (a full set resists 40%), matching vanilla Bedrock behavior. The total resistance is also synced to the client as an attribute, so client-side prediction matches the server.

When disabled, armor no longer contributes knockback resistance and players take knockback at full strength (legacy behavior). Knockback resistance from other sources, such as entity attributes set by plugins, is not affected.
